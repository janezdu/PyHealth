Does an invariance penalty move a generator along the specialist–generalist axis?

Each hospital is an IRM environment. Every client adds the squared gradient of its own loss with respect to a dummy classifier pinned at 1.0, summed unweighted so a 142-patient site counts as much as an 1,832-patient one. Every arm below trains the same 100 epochs, so the comparison is budget-matched on both sides. At ρ = 10² the penalty improves both axes on both arms it was run on.

The two targets

Every arm is scored twice against real code prevalences: against its own hospital's test fold, and against the pooled cohort fold. Up is a better specialist, right is a better generalist. Arrows run from the unpenalised run to its IRM counterpart. The view opens on the unpenalised runs and ρ = 10² only; the other ρ values and the late-start run are one click away.

Why centralized was down there

Codes emitted per synthetic visit, against the real cohort's 11.5. Pearson is a correlation, so it cannot see a uniform scale shift — an arm emitting a third of the real codes still scores well. What it does see is saturation: at 25 codes a visit the common codes pin near 100% prevalence, the differences between codes compress, and the rank ordering Pearson measures falls apart.

Reading it

The budget confound is ruled out, and the effect grew. The original baseline early-stopped at epoch 37, so the first version of this comparison gave the IRM arms 63 extra epochs. Re-run at a matched 100 epochs, centralized gets worse (0.580 → 0.527 specialist), not better — so the longer budget was never the advantage. The other three arms move by less than 0.02. The gap IRM closes is therefore larger than it first appeared: 0.527 → 0.823.
Starting late does not work. Holding ρ = 10² but delaying it to epoch 68 leaves centralized at R² −18.5 and RMSE 0.055, against −53.1 / 0.092 unpenalised and +0.31 / 0.013 when the same ρ starts at epoch 17. Thirty-two epochs of penalty only partly undoes sixty-eight epochs of saturation, so the penalty is preventing the runaway rather than repairing it. When it starts matters more than how large it is.
ρ is a threshold, not a dial. At 10², 10⁴ and 10⁵ the generator lands at 3.80, 3.82 and 3.82 codes per visit — indistinguishable. Once the penalty is large enough to stop the runaway, more of it changes nothing. The informative sweep is downward, to find where it stops working.

Before this is a result

  • One seed, two ρ values. No repeats, no confidence intervals. The centralized jump is large enough to survive most noise; the fedavg movements are not.
  • The budgets are not matched. The baseline fedavg early-stopped at round 34; the IRM runs were given --no-early-stop and trained all 50. The IRM arms therefore had ~16 more rounds. A --no-early-stop baseline is the missing control, and it is cheap — these runs take about seven minutes.
  • ρ is bracketed, not tuned. 10² and 10⁴ were chosen to straddle a plausible range. 10² is better or equal nearly everywhere, so the useful next sweep is downward, not upward.
  • Utility is unchanged. Rare-code TSTR average precision sits at 0.0100–0.0108 across all six runs — inside noise. IRM moved prevalence fidelity and did not move downstream classifier quality.
